Random search - the reference baseline

How Random search actually works

Not a smarter cousin of P3 - its opposite. Zero structure, zero memory, zero learning from history. From one idea, through the two procedures needed to implement it, to the question this simplicity poses to every more sophisticated algorithm that gets compared against it.

Laid out like a C4 diagram: context, then the big moving parts (there aren't many), then each one broken down in detail, then code, and finally a practical checklist.

1Context - why bother comparing against something this simple

In one sentence: random search draws points from the search space independently of each other, remembers the best result seen so far, and does literally nothing else.

No density model, no population, no linkage tree, no fidelity. Every evaluation is blind to all previous ones - neither where sampling has already happened nor what was found there. This makes it the cheapest possible baseline: if a method can't beat it at the same evaluation budget, all its extra machinery - surrogate, population, fidelity schedule - isn't earning its cost.

This is where this page differs from the rest of the series: the other pages describe methods that build something - a model, a population, a tree. This one describes a method that builds nothing, and that's exactly why it's the zero point of the GECCO 2027 P3Net paper. The paper compares P3Net in a nine-armed ablation grid against six other methods - NSGA-Net, NSGANetV2, SH-EMOA, MO-BOHB, TPE, and random search itself - on JAHS-Bench-201 and NAS-HPO-Bench-II. Random search stands at one end of that grid as the floor: no structure, no learning, no fidelity. Everything to the right of it in the series adds exactly one of those three things at a time.

The rest of this page breaks down that left edge of the diagram - exactly the two parts random search is made of, and nothing more.

2Big picture - one loop, two parts

In one sentence: sample a point, evaluate it, compare against the best so far, repeat - with no step that ever looks back.

PartJob
Search-space samplerDraws one point, pulling each dimension independently and uniformly from its domain. Knows nothing about the history of previous trials.
Best-so-far trackingCompares the freshly evaluated point against the current record holder and keeps the better of the two. This is the algorithm's entire “memory.”

That's all of it. Section 3 has nothing more to break down beyond these two points - there's no third part, because none exists.

3  Components - breaking down what's there

The two parts from the table above, now at the level of detail needed to implement them. Deliberately short - because that's really all there is.

3.1The search-space sampler

In one sentence: for each dimension separately, draw a value uniformly from its domain, assemble into one point, done.

No dependency between dimensions, no dependency on which points were sampled earlier, no dependency on how good or bad their results were. A categorical dimension draws one of the allowed values with equal probability; a continuous one draws uniformly from its interval (or from another distribution if you choose one, but still with no memory). This is the only place in the whole algorithm where problem-specific randomness appears at all.

What's not here

No l(x) or g(x) like in TPE, no gene-pair frequency table like in the P3 linkage tree, no population to sample a parent from. The sampler keeps no state between calls beyond the random number generator. Call it a million times - the millionth call knows nothing more about the problem than the first.

3.2Best-so-far tracking

In one sentence: after every evaluation, compare the result against the record holder; if it's strictly better, replace the record holder.

This is one variable (or, with multiple objectives, one Pareto front) and one comparison per iteration. No selection mechanism, no diversity pressure, no removing worse solutions from any structure - because there's no structure to remove them from. Points that don't beat the record are simply discarded: they don't join any population, don't influence future sampling, leave no trace beyond being counted against the budget.

For multiple objectives at once, the only change is the comparison rule: instead of a single strict inequality you use Pareto non-domination, and “best so far” becomes the front of non-dominated points instead of one point. The sampler itself doesn't change at all.

4.1The problem: the same deceptive genotype, a different algorithm

The demo below samples the same kind of genotype you'll meet on other pages in this series: 4 independent “traps” of 4 genes each (16 genes total). Within one trap the goal is a full set of four ones - but every step in that direction, unless it's a change of all four at once, is punished, not rewarded. The maximum possible fitness is 16 (all four traps at 1111).

Methods that learn which genes to hold together can deliberately exploit this - copy the whole cluster at once from someone who's already solved it. Random search has no such option: every point is an independent coin flip on each of the 16 genes separately. 5  Pseudocode - what you'd actually have to write

Two procedures. Shorter than anything else in this series - and that's the whole point, not an oversight.

procedure RANDOM-SEARCH(budget)
    best ← null
    for i in 1..budget do
        x ← SAMPLE()                         // §3.1, independent of all previous x
        f ← fitness(x)                        // one real evaluation, no shortcut
        if best is null or f > fitness(best) then
            best ← x                          // §3.2, strict comparison
    return best
procedure SAMPLE()
    x ← empty vector
    for each dimension d in search_space do
        x[d] ← random value uniformly from domain(d)   // §5.a: YOU define this domain
    return x

That's the whole algorithm. There's no mutation procedure, no crossover, no tree-building, no auxiliary structure at all - RANDOM-SEARCH calls SAMPLE once per iteration, and SAMPLE refers to nothing beyond each dimension's domain. The rest of this series is a description of what gets added to these two procedures - and at what price.

6  What you design yourself - applying random search to a real problem

The same split as the other pages in this series: the mechanism is fixed by the algorithm and fits into the two short procedures from section 5. What changes every time is how your problem plugs into that mechanism - and, in this case, how much budget you can even give it.

Decision pointFixed by the algorithmYou decide, per problem
Sampling Uniform, independent sampling of each dimension from its domain, with no memory between trials. The search-space encoding and decoder - how your problem becomes a vector of dimensions that can even be sampled uniformly.
Best tracking A plain argmax over fitness; ties don't replace the record holder. The fitness/objective definition - and, with multiple objectives, the non-domination rule you compare points by.
Evaluation budget The loop stops exactly after the given number of evaluations - no other stopping condition. The budget itself: how many evaluations you can afford. This is the algorithm's one parameter, and you have to choose it yourself every time.
Invalid points No built-in handling - the sampler doesn't know something like an “invalid point” exists. What to do with a sample outside the allowed set: reject and resample, repair it, or penalize it in the objective function.
The blind spot this page holds up to P3Net

Random search doesn't win on any problem with structure - exactly what the demo in section 4 shows: with no way to copy a whole trap cluster at once, the probability of hitting the global optimum drops exponentially with the number of traps. That's no surprise. The question this page actually answers is different: does P3Net's extra structure and cost - the linkage tree, the relative surrogate, the population pyramid - actually earn its keep at a given budget, or would blind, uniform sampling reach a comparable result more cheaply?

This question has no answer known in advance for every problem - it depends on how much actual structure (dependencies between architecture genes and hyperparameters) a given benchmark even has to exploit, and how expensive one real evaluation is. Random search is what you have to beat for the answer to that question to be “yes” - not because it's a good algorithm, but because it's the cheapest honest test.

✓Checklist for applying random search to a new problem

  • Define each dimension's domain: a finite set of values or an interval you can sample uniformly.
  • Define fitness as a single, strict comparison (or a non-domination rule, if there's more than one objective).
  • Decide what happens to samples that don't decode to a valid solution.
  • Set the evaluation budget up front - it's the only parameter you have to choose at all.
  • Run it as a baseline before you believe a more sophisticated method actually helps on your problem.
Source: J. Bergstra and Y. Bengio, “Random Search for Hyper-Parameter Optimization,” JMLR 2012 - the classic argument for random search as a baseline, which is what this method's role in the ablation grid above rests on.
